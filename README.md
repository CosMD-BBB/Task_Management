# Room · Team task management

เว็บจัดการงานในทีม พร้อมห้องโปรเจกต์ส่วนตัวและมุมมอง **List, Board, Calendar** ออกแบบสำหรับทีมคอนเทนต์ รองรับภาษาไทยและใช้งานบนมือถือได้

## สิ่งที่ใช้งานได้

- สมัครบัญชี, ยืนยันอีเมล, Login, Logout และรีเซ็ตรหัสผ่านผ่านลิงก์ใช้ครั้งเดียว รหัสผ่านเข้ารหัสด้วย bcrypt และ session เก็บในฐานข้อมูล
- สร้าง/แก้ไข/ลบห้องโปรเจกต์ เปลี่ยนชื่อและรูปประกอบ เจ้าของเชิญสมาชิกด้วยอีเมล และเลือก **Editor** หรือ **Viewer**
- API ตรวจสิทธิ์ทุกครั้ง ผู้ที่ไม่ได้เป็นสมาชิกจะมองไม่เห็นห้องหรืองาน แม้รู้ ID
- สร้าง/แก้ไข/ลบงาน เลือกสถานะโดยตรง ระบุ due date, priority และผู้รับผิดชอบหลายคนพร้อมการแจ้งเตือนภายในเว็บ
- สนทนาในแต่ละงานด้วยความคิดเห็น แคปชั่น หรือคำขอแก้ไข พิมพ์ @ เพื่อแท็กสมาชิกโปรเจกต์และแจ้งเตือนให้เปิดตรงข้อความนั้น เก็บข้อความพร้อมชื่อผู้เขียนและเวลาในฐานข้อมูล
- เลือก Type Content และ Channel หลายค่าเป็นกล่อง พร้อมเพิ่มตัวเลือกของแต่ละโปรเจกต์เอง ตัวเลือกยังอยู่แม้งานถูกลบ
- หน้าแก้ไขงานแสดงประเภทคอนเทนต์และช่องทางพร้อมกัน กดเลือกหลายรายการได้ทันที พร้อมช่องเพิ่มตัวเลือกใหม่และปุ่มบันทึกที่มองเห็นเสมอ
- โหมดสว่าง/มืดเลือกจากปุ่มมุมขวาบน จำค่าที่เลือกไว้ และใช้โหมดของอุปกรณ์ในครั้งแรก
- สีช่องทางตรงกับแพลตฟอร์ม และประเภทคอนเทนต์ใช้สีสดที่แยกกันชัดเจน สีเดียวกันทั้งกล่องเลือก ป้ายที่เลือก และมุมมองงาน
- แนบ **ลิงก์ไฟล์** Google Drive/Figma/URL, checklist และคอลัมน์กำหนดเองแบบข้อความหรือตัวเลือก
- List จัดกลุ่มสถานะ, Board ลากการ์ดหรือเปลี่ยนสถานะจากเมนู, Calendar แสดงงานตาม due date
- ค้นหา, กรองความสำคัญ/ช่องทาง/ผู้รับผิดชอบ, เรียงลำดับ และสรุปจำนวนงาน
- คลิกกล่องคอนเทนต์หรือช่องทางใน List เพื่อแก้ไขงานได้โดยตรง บนมือถือรายการงานแสดงเป็นการ์ดที่เห็นสถานะ คอนเทนต์ และช่องทางในจอเดียว
- ปุ่มทดลองใช้สร้างห้องตัวอย่างส่วนตัวแยกจากคนอื่น บัญชีทดลองเข้าซ้ำได้เฉพาะ session เดิม
- Super Admin มีหน้า **จัดการผู้ใช้งาน** สำหรับค้นหา แก้ชื่อ ระงับ/เปิดบัญชี และลบสมาชิก พร้อมย้ายเจ้าของโปรเจกต์ก่อนลบ

การแนบไฟล์เป็นการแนบลิงก์ ไม่ได้อัปโหลดไฟล์เข้าเว็บไซต์ สมาชิกต้องมีสิทธิ์เปิดไฟล์ที่บริการต้นทางด้วย

ข้อกำหนดฟอนต์ของ CosMD คือ **Manrope สำหรับอังกฤษและตัวเลข + Sukhumvit Thai สำหรับไทย** ต้องคงคู่นี้เมื่อปรับธีม สี หรือหน้าตาเว็บ ข้อกำหนดของผู้ใช้บันทึกใน [AGENTS.md](AGENTS.md) เพื่อใช้ต่อในโปรเจกต์นี้

Manrope ฝังเป็นไฟล์ในเว็บแล้ว ส่วน Sukhumvit Thai ใช้จากเครื่องเมื่อมีฟอนต์ติดตั้งอยู่ ยังต้องนำไฟล์แบรนด์จริงเข้าคลาวด์เพื่อให้ภาษาไทยเหมือนกันทุกอุปกรณ์ ดูแหล่งที่มาและไฟล์ที่ขาดใน [public/fonts/README.md](public/fonts/README.md)

## รันในเครื่องหรือ Codex Cloud

ใช้ Node.js **24.x** และ checkout เดิมที่ `/workspace/Task_Management` ไม่ต้องสร้าง Git worktree

```bash
cd /workspace/Task_Management
npm ci
# ใช้เฉพาะการทดสอบแบบจำลองที่ไม่มีข้อมูลจริง
MAIL_MODE=preview npm run dev
```

Vite รันพอร์ต 5173 และ proxy `/api` ไป Express พอร์ต 3000 สำหรับพัฒนา หากต้องการรันเว็บที่ build แล้ว:

```bash
npm run build
MAIL_MODE=preview npm start
```

Express ให้บริการทั้งหน้าเว็บและ API ที่พอร์ต 3000 `GET /api/health` ต้องตอบ `{ "status": "ok", "storage": "sqlite" }` และปุ่มทดลองใช้ต้องสร้างงานที่ดูและแก้ไขได้จริง

ฐานข้อมูล SQLite เก็บที่ `.data/workspace.sqlite` แบบ WAL และไม่ถูก commit ใน Git รีสตาร์ตแอปไม่ลบข้อมูล ตั้ง `SQLITE_PATH` เพื่อเปลี่ยนตำแหน่งได้ ก่อนสำรองฐานข้อมูลให้หยุดแอปหรือใช้ SQLite backup API และเก็บสำเนาอย่างปลอดภัย

## ทดสอบ

```bash
npm test
npm run build
MAIL_MODE=preview npm start
# อีก terminal; Chromium ในสภาพแวดล้อมนี้ติดตั้งที่ /usr/bin/chromium
npm run test:e2e
```

API tests ใช้ฐานข้อมูลชั่วคราวแยก ทดสอบ Login/session, สิทธิ์สมาชิก, การแยกข้อมูล, validation, CRUD และข้อมูลหลังเปิดฐานข้อมูลใหม่ E2E ใช้บัญชีแยกเพื่อทดสอบผ่านเบราว์เซอร์ ดู config สำหรับการเลือก executable ของ Chromium

## อีเมลและบัญชี Super Admin

เว็บตัวอย่างใช้ `MAIL_MODE=preview` จึงแสดง **กล่องอีเมลจำลอง** ของบัญชีที่ล็อกอินอยู่ ไม่มีการส่งอีเมลจริง บัญชีทดลองมี Super Admin เฉพาะข้อมูลตัวอย่างของตนเองและเข้าไม่ถึงบัญชีหรือโปรเจกต์จริง

สำหรับใช้งานจริง ให้เชื่อม [Resend](https://resend.com) และยืนยันโดเมนอีเมลผู้ส่ง แล้วตั้งค่าต่อไปนี้ผ่าน Environment Settings ของระบบโฮสต์:

- `RESEND_API_KEY`: ค่าลับของบริการ เก็บใน Settings เท่านั้น
- `MAIL_FROM`: ผู้ส่งที่ยืนยันโดเมนแล้ว เช่น `Room <info@cosmdskin.com>`
- `APP_URL`: HTTPS origin ของเว็บไซต์จริง เช่น `https://your-site.vercel.app` ไม่มี path หรือ query
- `SUPERADMIN_EMAIL`: `info@cosmdskin.com` ตามบัญชีที่เลือก

อย่าตั้ง `MAIL_MODE=preview` บนเว็บไซต์จริง แอปจะปฏิเสธการสมัครและส่งลิงก์หากการส่งอีเมลจริงยังตั้งค่าไม่ครบ Super Admin ตัวจริงจะได้รับสิทธิ์เมื่อสมัครและยืนยันอีเมลผ่านบริการจริงเท่านั้น ไม่ใช้รหัสผ่านกลางที่ฝังไว้ในโค้ด ผู้ที่มีแค่อีเมลตรงกันหรือยืนยันผ่านกล่องจำลองจะไม่ได้สิทธิ์นี้

หากเปลี่ยนฐานข้อมูลจากโหมดจำลองเป็นส่งอีเมลจริง บัญชีเดิมต้องยืนยันอีเมลใหม่ และลิงก์จำลองเก่าจะใช้งานไม่ได้ ลิงก์ยืนยัน/รีเซ็ตหมดอายุและใช้ได้ครั้งเดียว รีเซ็ตรหัสผ่านจะยกเลิก session เดิมทั้งหมด การระงับบัญชีจะตัด session และลิงก์กู้คืนทันที

ใน Codex Cloud ใช้ HTTPS proxy และ CA trust ของสภาพแวดล้อม สำหรับ Resend ต้องอนุญาต `api.resend.com` และผูก secret ไปยังโดเมนนี้โดยเฉพาะ ส่วน Vercel ให้เก็บค่าตรงใน Vercel Environment Variables

## ขึ้น Vercel พร้อมฐานข้อมูลถาวร

SQLite ของเครื่องพัฒนาใช้บน Vercel ไม่ได้ เพราะไฟล์ของ serverless ไม่คงอยู่ แอปรองรับ PostgreSQL ผ่าน `DATABASE_URL` และจะไม่เผลอใช้ SQLite บน Vercel

1. นำโค้ด repository นี้ขึ้น GitHub แล้ว Import Project ใน [Vercel](https://vercel.com/new)
2. เชื่อม [Neon](https://neon.tech) หรือ PostgreSQL provider ผ่าน Vercel Storage/Marketplace
3. เพิ่ม `DATABASE_URL` เป็น pooled PostgreSQL URL ใน Vercel Environment Variables ให้ทั้ง Preview และ Production เก็บค่าลับใน Settings เท่านั้น อย่าใส่ในโค้ดหรือแชต ต้องเปิด TLS พร้อมตรวจ certificate
4. ตั้งค่าอีเมลและ Super Admin ตามส่วนด้านบน โดยใช้ `APP_URL` ของโดเมนถาวรที่จะเปิดใช้งาน
5. ใช้ Node.js 24.x, install `npm ci`, build `npm run build`, output `dist` และ config `vercel.json` ที่ให้ไว้
6. Deploy แล้วตรวจ `/api/health` ต้องตอบ `storage: "postgres"` สมัครบัญชี ยืนยันอีเมล สร้างงาน รีโหลด และทดสอบการเข้าถึงด้วยอีกบัญชี

ฐานข้อมูลสร้างตารางและดัชนีอัตโนมัติจาก `server/database.js` การ deploy แต่ละครั้งไม่ลบข้อมูล ถ้าต้องย้ายข้อมูล SQLite เดิมเข้า Postgres ต้องมีขั้นตอน migration แยก **ไม่ได้ย้ายข้อมูลให้อัตโนมัติ**

เมื่อ GitHub เชื่อมกับ Vercel แล้ว commit ใหม่จะสร้าง deployment ใหม่ได้ ให้ Codex แก้โค้ดและทดสอบก่อน push หรือ review PR การแก้ settings/deploy ผ่าน Codex โดยตรงต้องเชื่อมบัญชีหรือให้สิทธิ์ Vercel ผ่านช่องทางที่ปลอดภัยก่อน

## ลิงก์ตัวอย่างชั่วคราว

เว็บในเครื่องเปิดให้ทีมภายนอกได้ผ่าน tunnel ที่ forward เฉพาะพอร์ต 3000 ลิงก์จะอยู่ได้เฉพาะช่วงที่ cloud machine, แอป และ tunnel ทำงาน ลิงก์นี้ไม่ใช่ hosting ถาวร เก็บ URL ที่บริการออกให้จริงเท่านั้น ไม่ใช้ localhost เป็นลิงก์สำหรับผู้ใช้ภายนอก

มี GitHub Actions workflow **Temporary website preview** สำหรับ repository นี้ โดย build/test แอปบน runner แล้วเปิด Cloudflare tunnel **30 นาที** ตรวจหน้าเว็บและ CRUD ผ่านลิงก์สาธารณะก่อนเผยแพร่ URL ที่ [preview-live/preview.json](https://github.com/CosMD-BBB/Task_Management/blob/preview-live/preview.json) รันใหม่ได้จาก Actions → Temporary website preview → Run workflow การเปลี่ยน source บน main จะเริ่มรอบใหม่และปิดรอบเก่า

ฐานข้อมูลของ preview runner แยกจากเครื่องพัฒนาและถูกลบเมื่อจบรอบ จึงควรใช้ข้อมูลทดลองเท่านั้น เว็บไซต์ถาวรต้องใช้ Vercel + Postgres ตามขั้นตอนด้านบน การเปิด preview ต้องมี GitHub Actions และสิทธิ์ workflow เขียน branch สำหรับ metadata

## ก่อนใช้จริงกับทีม

ระบบมีอีเมลยืนยันบัญชี/รีเซ็ตรหัสผ่านเมื่อเชื่อมบริการจริง และแจ้งเตือนการมอบหมายงานภายในเว็บ (รีเฟรชทุก 15 วินาทีหรือเมื่อกลับมาที่หน้าเว็บ) รูปโปรเจกต์อัปโหลด PNG/JPEG/WebP ได้โดยบีบอัดก่อนเก็บในฐานข้อมูล ส่วนไฟล์งานแนบเป็นลิงก์

ความคิดเห็นเปิดจากปุ่มรูปกล่องข้อความบนงาน หรือแท็บ **ความคิดเห็น** ในรายละเอียดงาน เลือกประเภทข้อความ พิมพ์ @ แล้วเลือกสมาชิก และกด **ส่งความคิดเห็น** สมาชิกที่ถูกแท็กจะได้รับแจ้งเตือนภายในเว็บ เจ้าของข้อความแก้ไข/ลบของตนได้ เจ้าของห้องลบข้อความในห้องได้ และ Viewer อ่านได้อย่างเดียว ข้อความใหม่รีเฟรชทุก 15 วินาทีหรือเมื่อกลับมาที่หน้าต่าง โดยคงร่างที่กำลังพิมพ์ไว้

ยังไม่มี OAuth, realtime synchronization ผ่าน WebSocket หรือการแจ้งเตือนงานทางอีเมล ต้องเชื่อมอีเมลจริงและฐานข้อมูลของระบบโฮสต์ พร้อมกำหนดการสำรองข้อมูลก่อนใช้งานกับทีมจริง การทดสอบในสภาพแวดล้อมนี้ใช้ SQLite; PostgreSQL และการส่งอีเมลจริงยังรอตั้งค่าบัญชีและทดสอบกับบริการจริง
