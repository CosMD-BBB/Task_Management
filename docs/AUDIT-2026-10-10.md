## สิ่งที่พบและแก้แล้ว

| จุดตรวจ | ผลและการปรับแก้ |
| --- | --- |
| PostgreSQL migration | เปลี่ยน session advisory lock เป็น transaction advisory lock; schema และข้อมูลเดิม commit/rollback พร้อม marker ใน `schema_migrations` การเริ่มหลาย instance ทำ migration สำเร็จครั้งเดียว และไม่เขียนข้อมูลทุกโปรเจกต์เมื่อเริ่มใหม่ |
| Connections และ timeout | Pool เริ่มต้น 3 connections ต่อ instance ปรับได้ด้วย `DATABASE_POOL_MAX` พร้อม timeout สำหรับการเชื่อมต่อ รับ connection query และ lock; รองรับ error ของ connection ที่ว่างอยู่ |
| Startup | เมื่อพอร์ตถูกใช้ แอปจบด้วย exit code 1 และไม่รายงานว่าเว็บไซต์พร้อม; Vercel ที่ไม่มี PostgreSQL ปฏิเสธการเริ่มแทนการสร้าง SQLite ชั่วคราว |
| Serverless initialization | คำขอพร้อมกันใช้ initialization เดียวกันและลองใหม่หลังความล้มเหลวได้ โดยตอบ 503 แบบไม่ cache |
| การบันทึกพร้อมกัน | ตรวจสิทธิ์ สมาชิก และข้อมูลปัจจุบันภายใน transaction; ลำดับ lock สอดคล้องกัน ลดการทับข้อมูลเมื่อแก้ field/สมาชิก/งานพร้อมกัน และรองรับ precondition ของเวอร์ชันงานเพื่อแจ้ง conflict |
| Login และ account links | ทดสอบการรีเซ็ตรหัสผ่าน/ระงับบัญชีขณะ login รอ รวมถึงการทำให้ลิงก์เดิมใช้ต่อไม่ได้ และการแยกบัญชีตัวอย่างออกจากการใช้งานจริง |
| ประวัติการจัดการ | มี audit log สำหรับการจัดการบัญชีโดยแอดมินอยู่แล้ว; ประวัติการเปลี่ยนงานและการกู้ค่าก่อนแก้ยังเป็นงานพัฒนาต่อ |
| Task editor และแท็ก | คลิกช่องคอนเทนต์/ช่องทางแล้วไปถึงตัวเลือกนั้นทันที; Enter ในช่องค้นหาไม่เผลอบันทึกงาน; เลือกหลายรายการได้พร้อมยอดที่เลือกและปุ่มดูตัวเลือกทั้งหมด |
| การกรองและโหลดข้อมูล | เพิ่มตัวกรองประเภทคอนเทนต์; ผลลัพธ์ว่างจากตัวกรองมีปุ่มล้าง; Calendar คงเดือนที่เลือก; แสดงปุ่มลองใหม่เมื่อโหลดโปรเจกต์หรืองานไม่สำเร็จ |
| ร่างงานและการทำงานร่วมกัน | รายการงานรีเฟรชทุก 15 วินาที/กลับมาที่หน้าต่างโดยคงร่าง; งานเวอร์ชันเก่าได้รับ 409 พร้อมข้อความและการยืนยันโหลดใหม่; การปิดตั้งค่าโปรเจกต์เตือนก่อนทิ้งร่าง |
| คำขอที่ตอบกลับช้า | ข้อมูลจากโปรเจกต์หรือบัญชีเก่าจะไม่เขียนกลับทับหน้าปัจจุบัน; ล้าง editor/แจ้งเตือนเมื่อเปลี่ยนบัญชี; จบสถานะโหลดหลังตั้งค่าโปรเจกต์และเปิดงานจากแจ้งเตือน |
| การเลือกผู้รับผิดชอบและแอดมิน | สมาชิกที่ระงับยังปรากฏในงานเก่าและเอาออกได้ แต่เลือกเพิ่มใหม่ไม่ได้; หน้าแอดมินแยกใช้งานได้/รอยืนยันอีเมล/ถูกระงับชัดเจน |
| Assets บน Vercel | ตรวจ routing จากแพ็กเกจทางการ `@vercel/routing-utils`: ระบบไฟล์ถูกประเมินก่อน rewrite จึงให้บริการ Manrope ที่มีอยู่ใน `dist/fonts` ได้ ไม่พบเหตุให้แก้ `vercel.json` สำหรับจุดนี้ |
| TLS และ cloud proxy | PostgreSQL ปฏิเสธ certificate ที่ไม่เชื่อถือ และเชื่อมต่อแบบเข้ารหัสเมื่อกำหนด CA ที่ถูกต้อง; native Node fetch ผ่าน proxy/CA ของ cloud ได้เมื่อเปิด `NODE_USE_ENV_PROXY=1` |

ผล PostgreSQL และ database/deployment มีกรณีทดสอบทับซ้อนกับชุดอื่น จึงไม่ควรนำจำนวนมาบวกเป็นยอดทดสอบอิสระทั้งหมด ใช้ PostgreSQL 17.11 ชั่วคราวผ่าน Docker บน loopback; ลบ container และฐานข้อมูลทดลองหลังทดสอบแล้ว ไม่ได้เชื่อม Neon หรือฐานข้อมูลทีมจริง

## งานเปิดใช้งานจริงที่ยังรอ

ยังไม่มี production credentials ที่พร้อมใช้งานใน cloud runtime รอบนี้ จึงยังไม่ได้ deploy Vercel จริง ทดสอบ Neon จริง หรือส่ง/รับอีเมล Resend จริง ไม่มีผล load test หรือจำนวนผู้ใช้สูงสุดที่ยืนยันแล้ว ทำขั้นตอนใน [คู่มือเปิดใช้งานจริง](PRODUCTION.md) ให้ครบก่อนประกาศเว็บไซต์พร้อมใช้งาน:

- แยกฐานข้อมูล Production/Preview ใช้ pooled URL พร้อม TLS ตรวจ certificate และตั้งค่าลับผ่าน Vercel Settings
- ยืนยันโดเมน Resend ตั้งผู้ส่ง, HTTPS `APP_URL` และ `SUPERADMIN_EMAIL=info@cosmdskin.com` แล้วทดสอบอีเมลยืนยัน/รีเซ็ตจริง; ห้ามใช้ `MAIL_MODE=preview` บน Production
- สมัครแอดมินด้วยรหัสผ่านของบัญชีเองและยืนยันอีเมลจริง ไม่ใช้รหัสผ่านกลาง
- เปิด backup/PITR และทดสอบ restore ไปฐานข้อมูลแยก พร้อมติดตาม function errors, connections และ email failures
- เพิ่ม distributed authentication rate limiting หรือ WAF ก่อนเปิดสมัครสาธารณะวงกว้าง; limiter ปัจจุบันแยกต่อ instance
- นำไฟล์ Sukhumvit Thai/Sukhumvit Set ของจริงที่มีสิทธิ์ใช้งานเข้าระบบและตรวจ desktop/mobile; Manrope มีไฟล์ฝังแล้ว แต่ภาษาไทยยังไม่ครบตามข้อกำหนดแบรนด์

## ขอบเขตสำหรับฟรีแลนซ์และลูกค้า

ระบบปัจจุบันมี Owner, Editor และ Viewer ในห้อง ผู้รับต้องสมัคร/ยืนยันบัญชีก่อนเจ้าของเพิ่มเป็นสมาชิก ยังไม่มี pending email invitation และ Viewer อ่านได้อย่างเดียวรวมถึงไม่สามารถส่งความคิดเห็นได้

งานพัฒนาลำดับถัดไปที่แนะนำคือ Commenter/Approver สำหรับลูกค้าที่ต้องให้ feedback โดยไม่แก้งาน, อีเมลเชิญ, ประวัติงาน และ Undo/ถังขยะ เมื่อจำนวนงานมากขึ้น ควรเพิ่มการแบ่งหน้ารายการ/เก็บงานเก่าและทดสอบโหลดตามขนาดทีมจริง การตรวจครั้งนี้ไม่ได้เพิ่มสิทธิ์หรือความสามารถเหล่านี้

การ Save/Publish ใน Codex เป็นการเตรียมสภาพแวดล้อมพัฒนา เว็บไซต์จริงจะเปลี่ยนผ่าน GitHub → Vercel หลังเชื่อม repository และ push commit ไป branch ที่กำหนดเท่านั้น รายงานนี้ไม่ยืนยันว่าการเชื่อมหรือ deployment นั้นเกิดขึ้นแล้ว
